# Hide H0.3 LKM interface audit: Xiaomi alioth

## 1. 决策

- [ ] Pass
- [ ] Conditional
- [ ] Kill
- [x] Unsupported / Blocked：当前内核没有可用于 exact hide 的稳定外部 LKM 接口。

本阶段只执行内核配置、导出符号和参考模块 KMI 审计。由于设备与 PathMask 发布矩阵
不匹配，且内核明确关闭 kprobe，不加载 `.ko`，不执行黑盒 PathMask 行为测试。

## 2. 设备内核

```text
Linux 4.19.157-perf-g9607d8651312
Xiaomi alioth / Android 13 / first API 30
Magisk 30.6
SELinux Enforcing
```

关键配置：

```text
CONFIG_MODULES=y
CONFIG_MODULE_UNLOAD=y
CONFIG_MODVERSIONS=y
CONFIG_KALLSYMS=y
# CONFIG_KPROBES is not set
# CONFIG_FANOTIFY is not set
# CONFIG_SECURITYFS is not set
CONFIG_BPF=y
CONFIG_BPF_SYSCALL=y
CONFIG_SECURITY=y
CONFIG_SECURITY_SELINUX=y
CONFIG_FUSE_FS=y
```

这不是“内核完全不能加载模块”，而是“没有 PathGuard 所需的动态策略挂接面”。设备
已经加载多个 OEM `.ko`，所以简单检查 `CONFIG_MODULES` 会得出错误乐观结论。

## 3. 符号审计

`/proc/kallsyms` 中存在：

```text
vfs_getattr
filename_lookup
do_filp_open
lookup_fast
iterate_dir
filldir64
security_inode_permission
security_inode_getattr
security_add_hooks
```

但 `__ksymtab_*` 只确认以下相关导出：

```text
__ksymtab_vfs_getattr
__ksymtab_iterate_dir
```

`lookup_fast`、`filename_lookup`、`filldir64` 是本地符号；`security_add_hooks` 和两个
security inode wrapper 没有模块导出。`vfs_getattr`/`iterate_dir` 是被调用入口，不是
允许外部模块注册 pre-lookup 或 dirent actor policy 的订阅接口。

因此在不修改内核的前提下，剩余手段只有 syscall/VFS inline patch、ftrace/kprobe 类
动态插桩或后处理用户缓冲。前两类在本机没有稳定注册面，后一类不能满足 fail-closed
exact semantics。

## 4. PathMask 对照

LKM-PathMask 的发布矩阵为：

```text
android12-5.10
android13-5.10 / 5.15
android14-5.15 / 6.1
android15-6.6
android16-6.12
```

本机 `android13-4.19` 不在矩阵中，仓库也没有预编译 `.ko`。PathMask 依赖
kprobe/kretprobe 解析辅助地址和拦截 VFS/syscall；本机 `CONFIG_KPROBES=n`，即使自行
编译一个 4.19 构件也不能按其设计注册 probe。

强行加载其他 KMI 的模块可能产生 `Unknown symbol`、`module_layout` 不匹配或内核崩溃，
且不会增加有效证据。因此 H0.3 的黑盒矩阵在本设备上是 `Unsupported`，不是待重试的
普通失败。

## 5. 结论

当前 stock/OEM 4.19 内核不存在可安全注册的 pre-lookup、directory-entry actor 和
namespace lifecycle 外部 ABI。按照 H0 约束：

- 不退回符号偏移扫描；
- 不开发 kprobe/ftrace/inline patch LKM；
- 不复制 PathMask 的 post-syscall return rewrite；
- 进入 H0.4 SUSFS ABI/设备能力核验。
