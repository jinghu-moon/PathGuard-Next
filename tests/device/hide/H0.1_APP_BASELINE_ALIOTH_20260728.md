# Hide H0.1 app-domain baseline: Xiaomi alioth

## 1. 结论

本次完成 `dev.pathguard.hideprobe` 在普通媒体读取权限配置下的 H0.1 app-domain
基线。Java `File`、NIO、JNI/libc、raw syscall、共享存储 alias、沙箱 mutation 和
MediaStore 均产生可解析证据；App 冷启动完成，无崩溃，测试沙箱无残留。

本报告是“没有 hide backend 时目标完整可见”的对照组，不是 hide 实现验证。
`hide.direct_vfs`、`hide.media_query` 和 `hide.mount_stealth` 均不得标记为通过。
H0.1 保持 **Conditional / In progress**，仍需 all-files 权限配置、非目标 App、系统
Photo Picker、SAF/DocumentsUI 和 CloudMediaProvider 矩阵。

## 4. Canonical 与 alias 基线

两个目标：

```text
/storage/emulated/0/Pictures/Nagram
/storage/emulated/0/DCIM/Screenshots
```

对 canonical 路径、`/sdcard` 和 `/storage/self/primary` 三组入口，Java、NIO、
libc 和 raw syscall 结果一致：

- `exists/isDirectory/stat/lstat/access/fstatat/statx` 成功；
- `open/openat/opendir` 成功；
- libc `readdir` 与 raw `getdents64` 均能枚举目标 basename；
- 已知路径没有被隐藏。

以下入口在当前 `untrusted_app` 域下均由现有平台权限先行拒绝，`stat` 返回
`-1/EACCES`，Java/NIO 显示不存在，parent 也不能打开：

```text
/mnt/user/0/primary/...
/mnt/runtime/default/emulated/0/...
/mnt/runtime/read/emulated/0/...
/mnt/runtime/write/emulated/0/...
/data/media/0/...
```

因此未来 backend 的必测 alias 是 App 实际可达的 canonical、`/sdcard` 和
`/storage/self/primary`。受平台权限保护的内部 alias 仍需保留回归，但不能把已有
`EACCES` 错当成 backend 实现的 `ENOENT`。

设备内核对 `openat2` 和 `faccessat2` 返回 `ENOSYS`；这与 shell-domain 基线一致。

## 5. Mutation 基线

所有 mutation 仅作用于 App 私有 `no_backup/pathguard-hide-h0-*` 沙箱：

| 操作 | 结果 | 已确认副作用 |
|---|---|---|
| Java `createNewFile` / NIO truncate | 成功 | 是 |
| Java `mkdir/delete/renameTo` | 成功 | 是 |
| native `openat(O_CREAT)` / `O_TRUNC` | 成功 | 是 |
| native `mkdirat/unlinkat/renameat` | 成功 | 是 |
| native `rmdir/renameat2/symlinkat` | 成功 | 是 |
| native `readlinkat` | 成功 | target 匹配 |
| native `linkat` | `-1/EACCES` | 否 |
| 对既有目录 `mkdirat` | `-1/EEXIST` | 否 |

结束记录 `java.probe.complete=0`、`probe.complete=0`。随后通过 `run-as find`
检查，未发现 `no_backup/pathguard-hide-h0-*` 残留。

这组成功副作用是未来 hide backend 的负向 oracle：命中 hide 后，相同操作必须失败，
且真实对象的 inode、mtime、size 和 content 不得变化。

## 6. MediaStore 基线

| 目标 | legacy query | Bundle query | direct URI open |
|---|---:|---:|---|
| `Pictures/Nagram/` | 2 | 2 | 成功 |
| `DCIM/Screenshots/` | 18 | 18 | 成功 |

projection 使用 `_ID`、`RELATIVE_PATH` 和 `DISPLAY_NAME`，Bundle query 只投影
`_ID`。这证明只过滤 `_data` 无法实现 `hide.media_query`；未来 Provider 能力还必须
阻止已知 content URI 的直接打开。
